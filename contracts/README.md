# Contracts

Pool, PolicyManager, RainfallOracle — Solidity, targeting Base.

**Status:** compiling and green — 51/51 tests pass on Foundry 1.8.3, and the
demo has been run end to end against a local anvil chain.

## Setup

Requires Foundry (`forge`, `cast`, `anvil`) and forge-std vendored into `lib/`:

```bash
curl -L https://foundry.paradigm.xyz | bash
~/.foundry/bin/foundryup
export PATH="$PATH:$HOME/.foundry/bin"
forge install foundry-rs/forge-std   # from contracts/
```

## Build and test

```bash
forge build
forge test -vv
```

`PayoutMath.t.sol` reads `test/vectors.json`, generated by the Python suite.
Regenerate it whenever the payout formula changes:

```bash
cd ../pricing && ../.venv/bin/python -m pytest tests/ -q
```

## Demo

Two scripts, because forge dry-runs a whole script against current chain state
before broadcasting: with settlement in the same script the simulation runs
before the clock advances and every `settlePhase` reverts `WindowNotClosed`.
The split suits the video anyway — pause after the policy is written, advance
the clock on camera, then settle.

```bash
anvil                                            # terminal 1
export PATH="$PATH:$HOME/.foundry/bin"
export SENDER=0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266

# 1. deploy, fund the pool, write the policy, publish the 2005 season
forge script script/Demo.s.sol:DemoSetup \
  --rpc-url http://localhost:8545 --broadcast --unlocked --sender $SENDER

# 2. fast-forward past the crop windows (the brief's "demo mode")
cast rpc evm_increaseTime 11232000 --rpc-url http://localhost:8545
cast rpc evm_mine --rpc-url http://localhost:8545

# 3. the payout moment — addresses are printed by step 1
POOL=0x... MANAGER=0x... POLICY_ID=1 \
forge script script/Demo.s.sol:DemoSettle \
  --rpc-url http://localhost:8545 --broadcast --unlocked --sender $SENDER
```

Verified output: pool capital 102,189 USDC → **88,989** after a **13,200 USDC**
payout on the 2005 flowering drought (134.8 mm against a 166 mm trigger),
reservation released to zero, policy closed.

## Design

**Pool** holds LP capital and enforces the solvency rule: `totalReserved` can
never exceed `totalAssets * solvencyRatioBps`. Both are public, so an observer
can verify the book is fully collateralised at any block. Capital backing an
active policy cannot be withdrawn.

**PolicyManager** merges the brief's Policy and Settlement contracts — they
share all their state, and splitting them would cost a cross-contract call per
settle for no isolation gain. Writing a policy reserves the full sum insured;
since phase weights sum to 10,000 bps, worst-case liability is exactly the sum
insured and the pool can never owe more than it locked.

`settlePhase` is **permissionless**. Once a window has closed and the oracle has
published, anyone can call it. The buyer files no claim and cannot be stalled.

**RainfallOracle** computes the median onchain from submitted feed values and
stores the inputs, so a reporter cannot publish a number that does not follow
from the sources it also published. It is a trusted-operator design at launch
and the pitch should say so; the decentralisation path is a threshold signer set
or Chainlink Functions behind the same interface.

| Quantity | Representation |

| Rainfall | hundredths of a mm (`mm * 100`) |

## Cross-language invariant

The payout formula exists twice — [PayoutMath.sol](src/PayoutMath.sol) and
`pricing/src/parametric/policy.py`. `test/vectors.json` is generated from the
Python and asserted against the Solidity. Change one, regenerate, run both
suites.

## Not done yet

- No reentrancy guard on `Pool`. Payout recipients are approved buyers and the
  asset is USDC, but this should be added before any real funds.
- `createPolicy` takes premium on trust from the caller — the pricing engine's
  number is not verified onchain. A signed quote would close that gap.
- No policy cancellation or refund path.
- Settlement assumes the oracle publishes once per phase and never corrects.
  A dispute/correction window is unbuilt.
